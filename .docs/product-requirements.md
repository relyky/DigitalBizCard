# 產品需求：電子名片網站

來源：`.docs/raw/DigitalBizCard_requirement.md` 與討論紀錄。標示「待確認」的項目尚無結論，不要自行假設。

## 願景

提供一個獨立小網站，讓員工把電子名片分享給客戶；客戶只要有該員工的名片網址就能查看。

## 階段

| 階段 | 目標 | 狀態 |
|---|---|---|
| 第一階段 | 驗證可行性：把 Marp 名片渲染成網頁並顯示 QR code | 進行中 |
| 第二階段 | 員工電子名片資料維護 | 待第一階段完成再規劃，**本文件不涵蓋** |

## 第一階段範圍

### 要做
1. 以 Next.js 建立獨立網站，僅用於分享名片。
2. 讀取 4 份 Marp 範例檔（郝聰明、甄美麗、艾漂亮、高又壯），渲染為網頁。
3. 名片網址：`/bizcard/<staff-shared-uuid>`，每個 uuid 對應一份名片。
4. 渲染兩種 QR code：LINE 加好友、vCard 加入通訊錄。

### 不做
- 資料庫與資料表（`biz_card`、`staff_headshot`）。
- 名片資料維護、登入、後台。
- 隱私與存取控制。
- 真實資料；範例內容與 QR code 內容皆為假資料。

## 已確認的決策

| 項目 | 決策 |
|---|---|
| 資料來源 | 直接讀取 4 份 Marp 範例檔，不使用資料庫 |
| 隱私與安全 | 第一階段不處理。名片本質上公開，知道網址即可查看 |
| QR code 產生 | 第一階段使用外部服務 `api.qrserver.com`，資料皆為假資料；確認可行後才改用真實資料 |
| 使用者與情境 | 客戶已從員工取得名片網址，直接用瀏覽器開啟查看 |
| uuid 對應 | 暫時寫死在程式碼（見下表） |
| uuid 不存在 | 顯示 404 |
| 非功能需求 | 無 |
| LINE 連結 | 沿用 Marp 範例中的假資料 |
| 第二階段 QR code | 預計改為本機產生，到該階段再處理 |

### 暫定 uuid 對應

| 員工 | uuid |
|---|---|
| 郝聰明 | `a1123456789012345678901234567890` |
| 甄美麗 | `b2123456789012345678901234567890` |
| 艾漂亮 | `c3123456789012345678901234567890` |
| 高又壯 | `d4123456789012345678901234567890` |


## 成功標準

- 4 份範例都能以各自網址正確顯示，版面與 Marp 預覽一致。
- 兩種 QR code 都能顯示，且手機掃描可用（LINE 連結、vCard 匯入通訊錄）。
- 網址中的 uuid 不存在時回應 404。
